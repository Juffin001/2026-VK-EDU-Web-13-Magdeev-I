## ДЗ3. Запуск сайта вопросов и ответов

Команды выполняются из каталога с `docker-compose.yml`. Для запуска в контейнерах нужен Docker Compose. Для запуска Django на хосте нужен также Python 3.14.

### Первый запуск через Docker Compose

1. Создай `.env.docker` из шаблона командой `cp .env.example .env.docker`. Если файл уже настроен, используй его. При первом запуске задай в нём свои `SECRET_KEY` и `DB_PASSWORD`. Оставь `DB_HOST=db` и `DB_PORT=5432`. Django и PostgreSQL получат параметры из одного файла.
2. Собери образы, запусти сервисы и создай таблицы.

   ```sh
   docker compose --env-file .env.docker up -d --build
   docker compose --env-file .env.docker exec web python manage.py migrate
   ```

3. Создай администратора и задай пароль в терминале.

   ```sh
   docker compose --env-file .env.docker exec web python manage.py createsuperuser
   ```

Открой [главную](http://127.0.0.1:8000/) или [админку](http://127.0.0.1:8000/admin/). После миграций на пустой базе главная покажет сообщение «Пока нет ни одного вопроса». Данные PostgreSQL хранятся в томе `postgres_data`.

### Локальный запуск Django с PostgreSQL в Docker

Для первого запуска подготовь `.env.docker`, как описано выше. Если `.env.local` ещё нет, скопируй в него `.env.docker`. В `.env.local` укажи `DB_HOST=127.0.0.1` и `DB_PORT=5433`. Имя базы, пользователь и пароль должны совпадать с настройками работающей базы.

```sh
docker compose --env-file .env.docker up -d db
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python web/manage.py migrate
python web/manage.py runserver
```

Если контейнер `web` уже занимает порт 8000, локальный сервер можно запустить на другом порту командой `python web/manage.py runserver 8001`.

### Наполнение и проверка

`fill_db` добавляет новую порцию данных при каждом запуске. Для знакомства с сайтом на пустой базе выполни:

```sh
docker compose --env-file .env.docker exec web python manage.py fill_db 2
```

Коэффициент 2 добавит 2 пользователей с профилями, 2 тега, 20 вопросов, 200 ответов и 400 оценок. Для первой порции нужны хотя бы два тестовых пользователя из-за ограничения на повторную оценку. Для полного объёма ДЗ на чистой базе укажи `10001`. Если уже выполнен `fill_db 10000`, достаточно добавить `fill_db 1`, чтобы превысить все пороги. При локальном запуске эквивалентная команда имеет вид `python web/manage.py fill_db 2`.

- На главной вопросы отсортированы по дате. На [странице лучших вопросов](http://127.0.0.1:8000/hot/) первыми идут вопросы с высоким рейтингом.
- Клик по тегу открывает вопросы с этим тегом. Клик по заголовку или числу ответов открывает вопрос. В списках выводится по 20 вопросов, на странице вопроса — по 30 ответов.
- Для проверки SQL открой сайт с `DEBUG=True` и выбери панель SQL в Django Debug Toolbar. На главной теги карточек загружаются одним запросом, а ответы подсчитываются только для вопросов текущей страницы.

Тесты пагинации и счётчиков запускаются командой `docker compose --env-file .env.docker exec web python manage.py test questions`. При локальном запуске с активным виртуальным окружением выполни `python web/manage.py test questions`. Django создаёт отдельную тестовую базу.

Проект сделан с помощью bootatrapа, который подгружается через интернет, хотя его немного - всего одна кнопка, по большей части все сам старался писать. Также чтобы не повторять код (хеадер, сайдбар) с помощью js во все файлы вставляются соответственные куски кода из папки partials. Я запускал сайт с помощью live server в vs code. Весь css находится в файле base_style.css. Страница профиля является страницой настройкой профиля, поэтому место profile.html занимает settings.html (изначально я ориентировался на рисунки макетов, где эта страница и называется settings.html).  

Реализованные страницы  
index.html - главная (список вопросов)  
question.html - страница одного вопроса и ответы под ним  
tag.html - страница тега  
ask.html - форма добавления вопроса  
login.html - вход  
signup.html - регистрация
